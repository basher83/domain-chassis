# ADR-002: Triage Cold-Review as a Standalone Pi-SDK Reviewer

**Status:** Proposed
**Date:** 2026-06-01T03:35:12Z
**Authors:** Brent, Claude
**Reviewers:** Brent

## Context

The triage skill's Step 3 cold review is the gate before a `Q{n}-why.md` becomes a queue row: a fresh-context reviewer runs three probes (under-climb, cold smell-test, direction-vs-destination) and returns a structured `N/5` verdict that Step 4 turns into PASS/FAIL. Until now Step 3 dispatched an in-context subagent via the Agent tool. That mechanism isolates *context* (a fresh window) but not *prompt fidelity*: the parent composes the review briefing freely each run, so nothing structurally prevents it from enriching the prompt beyond the artifact path — the exact delegation-boundary failure mode catalogued in `workshop-polish/analysis/commit-craft-failure-mode/context-corruption-memo.md`. Prompt fidelity was left to the parent's good behavior.

This ADR records the decisions made building the reviewer as a standalone script (queue item Q66), which is Phase 0 of the B3 gate-loop blueprint (`blueprints/B3-gate-loop-pi-extension.md`) — the pilot that tests whether a Pi cold judge reaches the operator's threshold on *fuzzy* criteria before the full extension is built on that assumption.

## Decision

Build the triage cold review as a standalone bun + Pi-SDK reviewer at `skills/triage/scripts/cold-review.ts`, invoked from triage Step 3 with a single `Bash` call whose sole interface is the absolute artifact path. The skill owns the reviewer because the reviewer *is* the code.

### Key decision factors

- **Argv-only interface = mechanical prompt-fidelity boundary.** The constructed review prompt is a pure function of the file at the positional path argument. Environment variables and stdin are never read into the prompt; an extra positional argument is a hard error. The parent cannot inject context into the review even when it tries — verified by a byte-identical (sha256) prompt across a clean run and one carrying adversarial env + stdin payloads. This is the strongest tier of the delegation-boundary spectrum: the parent can't enrich because the interface doesn't accept enrichment, reached by `process.argv` parsing rather than by trusting a runtime to honor `context: fork` or a prose "do not enrich" instruction.
- **The review prompt is a version-controlled contract.** The three probes and the `N/5` (5 declared unreachable) + per-probe findings + L3-residue + blocking-deficiency shape are hard-coded in the script. The model produces only those components; the PASS/FAIL verdict is derived deterministically *in the script* (PASS iff confidence ≥ 4 and no blocking deficiency), never by the model. Applying the verdict to the queue gate remains triage Step 4's job — the script returns the reviewer's components, preserving the existing division of labor.
- **Model + auth resolution reuses Pi's own registry.** The script builds `ModelRegistry.create(AuthStorage.create())` from `@earendil-works/pi-coding-agent`, reading the operator's Pi config at `~/.pi/agent/{models.json,auth.json}`, then calls `completeSimple()` from `@earendil-works/pi-ai`. This is the same mechanism `upstream/pi-until-done/tools/judge.ts` uses, reused rather than reinvented, and it gives the reviewer every provider the operator's Pi is authed for (Anthropic via the OAuth proxy, GPT via Codex OAuth, Google via env key).
- **Default model `anthropic-proxy/claude-sonnet-4-6`.** The original triage cold-review was a Claude subagent, so a Claude reviewer is faithful to the calibration that produced the operator's existing labels. Sonnet matches the operator's PASS@4 on the real on-disk records; Gemini over-fires and is treated as a non-blocking off-target. `--model provider/modelId` overrides for cross-family review; Anthropic and GPT are the supported targets.
- **Default effort `off` — the load-bearing finding.** Counterintuitively for a "judge," reasoning degrades this reviewer on two axes. (1) *Over-firing*: at low/medium/high the model reasons itself into firing the smell-test probe on well-carved artifacts — those pairing a self-contained near-term step with an explicit carve — diverging from the operator's calibration. (2) *Non-determinism*: thinking is stochastic even at temperature 0, so verdicts flicker run-to-run at the PASS/FAIL boundary. At `off` (no thinking) the judge is one-pass: stable and calibrated. Evidence (2026-06-01): `Q66-why` core scored 5/5 PASS@4 at off vs 4/5 FAIL@3 at low; `Q67-why` core scored PASS@4 at off vs FAIL@3 at low. Discrimination on a genuinely-flawed artifact held at *every* effort (FAIL@1, all three probes). The effort lever is therefore load-bearing and floored at off for this fuzzy criterion; `--effort` can raise it for experimentation.
- **Temperature gated on OAuth.** Temperature 0 is the reproducibility floor for direct-API providers (Google env key, the Anthropic proxy — `isUsingOAuth` false). OAuth-brokered Codex rejects `temperature` with HTTP 400 "Unsupported parameter," so the option is set only when `!registry.isUsingOAuth(model)`. (With effort floored at off, temperature 0 on the default Anthropic-proxy path is the active reproducibility mechanism.)
- **Fail-closed and loud.** A missing runtime, missing/!ok credential, unreadable artifact, model error, or unparseable response produces a loud non-zero exit (codes 2/3/4) and emits no verdict on stdout. There is no silent skip and no fall-back to the old in-context dispatch — a fallback would reintroduce the unenforced boundary this reviewer exists to remove. A provider error returned as `stopReason: "error"` (not a thrown exception) is surfaced with its real cause rather than mislabeled as a parse failure.

## Scope

This ADR and the reviewer it documents cover **triage's cold review only**. Gate-review's cold review shares the pattern (a Pi-SDK reviewer, artifact-path-as-argv, structured verdict) and the operator intends it isolated the same way, but adopting it as a second consumer — and deciding whether the two converge on one `--probe-set`-flagged script or remain two scripts sharing a harness — is **deferred to its own queue item**. This is not yet the standard for all chassis cold reviews; it is the triage instance, proven first. (Scope is named explicitly to avoid generalizing a single-consumer result into chassis-wide doctrine.)

## Consequences

- **The chassis gains a bun + Pi-SDK + credential dependency at triage-review time.** This is a deliberate step toward Pi (per B3), not a regression against a portability guarantee — the chassis is a Claude Code plugin, not a harness-agnostic artifact. Dependencies are **not** committed (gitignored), and the plugin cache (`${CLAUDE_PLUGIN_ROOT}`) is read-only and per-version, so they cannot be installed there. Instead a chassis `SessionStart` hook (`hooks/hooks.json` → `hooks/ensure-reviewer-deps.sh`) installs them into the plugin's **persistent** data dir, `${CLAUDE_PLUGIN_DATA}/node_modules` (which survives plugin updates), reinstalling only when `skills/triage/scripts/package.json` changes; the reviewer resolves them via `NODE_PATH`. This is the documented Claude Code pattern for plugin npm dependencies (plugins-reference: "Use [`${CLAUDE_PLUGIN_DATA}`] for installed dependencies such as `node_modules`"). The remaining runtime prerequisites are bun on PATH and a Pi-configured credential under `~/.pi/agent`; where either is absent, the triage cold review fails closed and loud. (Initial Q66 delivery mis-stated this as a manual `bun install` in the script dir — corrected here; the script dir is the read-only cache. The `SessionStart` hook is the chassis's first hook.)
- **Cross-domain delivery is version-gated, distribution operator-controlled.** The change reaches other domains through a lockstep plugin-manifest bump and commit; the plugin-cache refresh and the per-environment `bun install` are operator/platform actions outside the authoring agent's control.
- **B3 input.** The pilot answers B3's load-bearing open question with a caveat: a Pi cold judge *does* reach the operator's threshold on fuzzy triage criteria — but only with thinking off; reasoning effort both over-fires and destabilizes it. B3's Layer-2 judge design must treat effort as a calibrated parameter, not maximize it, and should weigh multi-sample voting if a thinking model is ever required.
- **Resolved (Q70) — smell-test probe wording is now carve-aware.** The smell-test probe as originally ported was literally ambiguous: "read the Near-term step *alone* … if it could be the entire endstate, the narrowing is silent → finding," read in isolation, ignores that an explicit *carve* is what makes a narrowing non-silent. At effort off the model applied it holistically and matched the operator; under reasoning it applied the literal text and over-fired (the line-24 baseline: `real-Q66-core` → 4/5 `FAIL@3` at low). Q70 reworded the probe in the version-controlled contract (the smell-test entry of `SYSTEM_PROMPT` in `skills/triage/scripts/cold-review.ts`) to carry two properties: (i) it reads the Near-term step *together with the carve* — a self-contained near-term step paired with a genuine carve that names the deferred larger shape is non-silent and NOT a finding, which closes the literal ambiguity; and (ii) it stays adversarial — if the near-term step genuinely *is* the whole endstate and the asserted carve is hollow (claims to defer a larger shape that does not exist beyond the step), the narrowing is silent in substance and still a finding (carve-aware, not carve-trusting). Scope: the smell-test probe **only** — the under-climb and direction-vs-destination probes are unchanged. Validated in Q70 gate-work (`gates/Q70-gate.md`): no regression at the calibrated default (well-carved real cores still `PASS@4`, a genuinely-flawed record still `FAIL`, zero flicker) and materially less over-firing than the old text under reasoning effort `low`, measured as a same-session paired run.
